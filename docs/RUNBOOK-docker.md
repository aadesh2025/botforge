# RUNBOOK — Bringing the Docker stack up (Windows)

Practical steps to boot BotForge locally and verify Phase 0 + Phase 1 against a real
Postgres. Assumes Windows + Docker Desktop + PowerShell. Compose file lives at
`infra/docker-compose.yml` and reads `.env` from the **repo root**.

> Status: **Phase 1 is verified.** Both migrations are committed — `0001_extensions`
> (pgcrypto/vector) and `008762f7f63b_initial_schema` (all 27 tables, autogenerated from the
> models per `DECISIONS.md` ADR-014). A fresh DB now just needs `alembic upgrade head` +
> `seed` (Step 6); no autogenerate needed unless you change the models.

## Prerequisites
- **Docker Desktop** running (whale icon = "running"; WSL2 backend enabled).
- Repo at `E:\AUROZEN AGENCY\own_chatbot`.

## Step 1 — Open PowerShell at the repo root
```powershell
cd "E:\AUROZEN AGENCY\own_chatbot"
```

## Step 2 — Create `.env` at the repo root (NOT in infra/)
```powershell
Copy-Item .env.example .env
```

## Step 3 — Set a real SECRET_KEY
Generate one in PowerShell (no Python needed):
```powershell
-join ((48..57)+(65..90)+(97..122) | Get-Random -Count 48 | % {[char]$_})
```
Open `.env`, replace the `SECRET_KEY=change-me...` line with the output. Leave every
`[HUMAN]` key (Groq/OpenAI/OAuth/channels) blank for now — none are needed to boot.

## Step 4 — Bring up just the database first (fast path for Phase 1)
Avoids the slow Ollama pull + web `npm install` on the first run.
```powershell
docker compose -f infra/docker-compose.yml up -d postgres redis
docker compose -f infra/docker-compose.yml ps
```
Wait until `postgres` shows **healthy**.

## Step 5 — (optional) sanity-check Postgres + pgvector
```powershell
docker compose -f infra/docker-compose.yml exec postgres psql -U botforge -d botforge -c "SELECT version();"
```

## Step 6 — Create the schema and seed demo data
Both migrations are committed, so this is just apply + seed. Run from `apps\api` on the host
(reads the root `.env`; `DATABASE_URL` points at `localhost:5432`):
```powershell
cd apps\api
uv run alembic upgrade head          # applies 0001_extensions + the 27-table migration
uv run python -m app.db.seed         # idempotent: 1 org, 1 owner, 1 agent+version, 2 docs, 1 tool, 1 channel
```
Verify:
```powershell
docker compose -f ..\infra\docker-compose.yml exec postgres `
  psql -U botforge -d botforge -tAc "SELECT count(*) FROM information_schema.tables WHERE table_schema='public';"
# → 28  (27 tables + alembic_version)
```

> If you later change the models, regenerate with
> `uv run alembic revision --autogenerate -m "..."`. A pgvector column needs
> `import pgvector.sqlalchemy.vector` at the top of the generated file (add it if missing).
> `alembic revision --autogenerate` requires the DB to be at head first (`upgrade head`).

## Step 7 — Bring up the full stack (when ready)
Pulls the larger images (n8n, ollama) and installs web deps on first run.
```powershell
docker compose -f infra/docker-compose.yml up -d
```
Verify the API is green (Postgres + Redis reachable):
```powershell
curl http://localhost:8000/readyz
```
A `200` means Phase 0 + 1 are verified end-to-end.

## Everyday commands
```powershell
docker compose -f infra/docker-compose.yml up -d        # start (detached)
docker compose -f infra/docker-compose.yml ps           # status
docker compose -f infra/docker-compose.yml logs -f api  # tail one service
docker compose -f infra/docker-compose.yml down         # stop (keeps data volumes)
docker compose -f infra/docker-compose.yml down -v      # stop + WIPE data (fresh DB)
```


## Troubleshooting
- **Port already in use** (5432/6379/5678/11434/3000/8000): another app holds the port.
  Stop it, or change the left-hand `host:container` port in `infra/docker-compose.yml`
  (e.g. `"5433:5432"`) and update `DATABASE_URL` accordingly.
- **`.env` not picked up**: it must be at the repo root, not in `infra/`. The compose file
  references `../.env`.
- **api/web won't start on first `up`**: named volumes (`api_venv`, `web_node_modules`) fill
  on first run — give the initial `npm install` / `uv sync` a couple of minutes; check
  `logs -f web` / `logs -f api`.
- **`/readyz` returns 503**: a datastore isn't reachable. Check `docker compose ps` health and
  that `.env` `DATABASE_URL`/`REDIS_URL` use `localhost` when the API runs on the host.
- **Reset everything**: `docker compose -f infra/docker-compose.yml down -v` wipes Postgres,
  Redis, n8n, and Ollama volumes for a clean slate, then re-run Step 6.
